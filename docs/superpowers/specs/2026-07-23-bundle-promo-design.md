# מבצע חבילה (1+1 / 2+1) + תיחום בתאריך — עיצוב

**תאריך:** 23.7.2026 · **אושר ע"י רועי**

## הצורך
לרועי אין כיום דרך להגדיר מבצע "קנה X קבל Y" (1+1, 2+1) בקטלוג ההיגיינה, ואין דרך לתחום מבצע
בתאריכים. כיום קיימים רק: מבצע פרטני (`original_price` — מחיר מוזל), הנחת קטגוריה, הנחת סל ובאנר —
כולם ללא תוקף. מבצעי חבילה הם תבנית קמעונאית מרכזית, ותיחום בתאריך חוסך את הצורך לזכור לבטל מבצע.

## החלטות שרועי אישר
1. **היקף:** פר מוצר (לא קטגוריה/גלובלי).
2. **חישוב:** תווית **וגם** חישוב אמיתי בעגלה — לקוח שמוסיף 2 ב-1+1 משלם על 1. (הימנעות ממצב שבו
   מוצג "1+1" אבל הסה"כ מחייב על שתיים — זו הטעיה.)
3. **תאריכים:** חלון גלובלי כברירת מחדל + דריסה פר מוצר.

## מודל נתונים

### CSV (מאסטר + ציבורי) — 3 עמודות חדשות
| עמודה | פורמט | משמעות |
|---|---|---|
| `bundle` | `"1+1"` / `"2+1"` / `"3+1"` | קנה X קבל Y. ריק = אין מבצע חבילה. |
| `promo_start` | `YYYY-MM-DD` (אופציונלי) | תחילת תוקף המבצעים של המוצר. ריק = חלון גלובלי. |
| `promo_end` | `YYYY-MM-DD` (אופציונלי) | סוף תוקף. ריק = חלון גלובלי. |

`promo_start/end` חלים על **כל** המבצעים של אותו מוצר — גם `bundle` וגם מחיר המבצע שלו.

### `data/pricelist-promo.json` — חלון גלובלי
```json
"window": { "starts": "2026-07-25", "ends": "2026-08-10" }
```
מחרוזות ריקות = בלי הגבלה. חל על באנר, הנחת סל, הנחות קטגוריה, ועל מוצרים בלי תאריכים משלהם.

## לוגיקה

### `promoActive(start, end)` — משותף לשרת ולקליינט
מוצר/מבצע פעיל אם התאריך של היום בתוך החלון (כולל קצוות). ריק = ללא הגבלה מאותו צד.
פר מוצר גובר על הגלובלי (אם למוצר יש `promo_start`/`promo_end` — הם קובעים).

### `chargeableQty(product, qty)` — app.js
```
group = buy + free
freeUnits = floor(qty / group) * free
return qty - freeUnits
```
2+1 עם 7 יחידות → 2 קבוצות (6 יח') → 2 חינם → מחויב על 5.
המחיר ליחידה **לא** משתנה; רק הכמות בתשלום. מיושם ב-4 מקומות שבהם מחושב סה"כ:
`updateSummary`, שורת טבלת ההזמנה, הודעת ההזמנה, וסיכום הסל.

## תצוגה
- **כרטיס מוצר + תצוגה מהירה:** תווית קטנה `1+1` מתחת למחיר (`.bundle-badge`, ירוק המותג —
  להבדיל מתג "מבצע" האדום).
- **טבלת ההזמנה:** סה"כ השורה מגלם את ההנחה; ציון קטן של מספר היחידות שחינם.
- **באנר `/care/`:** שקופית לכל מוצר בחבילה, ו**"בתוקף עד DD.MM" בטקסט קטן** כשקיים חלון.
- **קטגוריית "מבצעים":** כוללת גם מוצרי חבילה (לא רק `original_price > price`).

## עורך (`/admin/pricelist.html`)
- טופס המוצר: בחירת "מבצע חבילה" (ללא / 1+1 / 2+1 / 3+1) + שדות "תוקף: מתאריך / עד תאריך".
- "חבילה לנבחרים" ליד "מבצע לנבחרים" הקיים — החלה או ביטול לכל המסומנים.
- כרטיס המבצעים הכלליים: שני שדות תאריך לחלון הגלובלי.
- עמודה בטבלה שמציגה את החבילה.

## חשיפה חיצונית
- **פיד Merchant:** `g:sale_price_effective_date` עם החלון — גוגל מפסיק את המבצע בזמן בעצמו.
- **סכמת Product:** `priceValidUntil` עם תאריך הסיום.

## מגבלה מתועדת (אתר סטטי)
`/care/` מתקן את עצמו בדפדפן (app.js בודק תאריך בזמן אמת), אבל דפי הקטגוריה/מוצר הסטטיים,
הסכמה והפיד נבנים **בזמן שמירה בעורך**. מבצע שפג לא ייכתב מחדש, אך תוכן שנבנה לפני שהמבצע פג
יישאר עד השמירה הבאה. `sale_price_effective_date` ו-`priceValidUntil` מכסים את הצד של גוגל.
פרקטית: אחרי סיום מבצע — שמירה אחת בעורך מרעננת הכול.

## מחוץ לתחום
`data/products.csv` (קטלוג B2B) ודף הסוכן — אין להם עמודת `bundle`, ולכן אפס השפעה. כל השינויים
ב-app.js additive ומוגנים בבדיקת קיום השדה.

## אימות
1. עורך: הגדרת 2+1 למוצר + תאריכים; שמירה → העמודות נכתבות לשני ה-CSV.
2. `/care/`: תווית `1+1`/`2+1` בכרטיס ובתצוגה מהירה.
3. עגלה: 1+1 עם 2 יח' → מחויב על 1; 2+1 עם 7 יח' → מחויב על 5; סה"כ שורה, סה"כ סל והודעת
   הוואטסאפ עקביים.
4. תאריכים: מבצע עם `promo_end` בעבר → לא מוצג ולא מחושב. חלון גלובלי שפג → הנחות קטגוריה/סל כבויות.
5. באנר: שקופית חבילה + "בתוקף עד" בקטן.
6. פיד: `g:sale_price_effective_date` תקין; סכמה: `priceValidUntil`.
7. קטלוג B2B ודף הסוכן — אפס שינוי בהתנהגות.
8. מובייל 375px, אפס שגיאות קונסול.

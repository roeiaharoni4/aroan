# תצוגת סל מלאת-מסך עם כתובת משלה

**תאריך:** 2.8.2026
**סטטוס:** מאושר לביצוע

## הבעיה

רועי ביקש להחליף את חלון "סיכום הזמנה" בדף. שתי בעיות נפרדות עומדות מאחורי הבקשה, ולכל אחת פתרון אחר:

1. **החלון נראה צפוף ולא מקצועי.** אחרי סבב 30 המודאל בקטלוג הטיפוח מכיל טבלת מוצרים, בורר שיטת אספקה, בורר אופן תשלום, טופס לקוח בן חמישה שדות ושני נאדג'ים — 150 שורות HTML בתוך חלון צר, שכולו גלילה במובייל.
2. **אין דרך לדעת מי נוטש את הסל.** למודאל אין כתובת, ולכן ב-GA4 אין `page_view` לשלב הזה. אירוע `begin_checkout` קיים מסבב 29, אבל בלי URL אי אפשר לבנות קהל רימרקטינג של "הגיע לסל ולא הזמין" — הקהל הרווחי ביותר לקמפיינים שמתוכננים בסבב הבא.

בנוסף, במובייל כפתור "אחורה" מוציא היום את הלקוח מהקטלוג לגמרי במקום לסגור את הסל.

## ההחלטה

נבחרה **גישה א': תצוגת סל מלאת-מסך באותו עמוד, עם `?view=cart` בכתובת** — ולא דף נפרד (`/catalog/cart/`).

מבחינת הלקוח שתי הגישות זהות: מסך מלא, כתובת משלו, כפתור "אחורה" עובד. ההבדל פנימי בלבד — דף נפרד היה מחייב טעינה מחדש של `products.csv`, המבצעים והמשלוחים כדי לרנדר את הסל, כלומר השהיה בדיוק ברגע הכוונה הגבוהה ביותר, וכן שכפול הדר/פוטר ומצב "סל בלבד" ב-`app.js`. הלקוח לא מקבל דבר תמורת המחיר הזה.

**היקף:** הקטלוג העסקי (`/catalog/` + 10 דפי הקטגוריה) וקטלוג הטיפוח (`/care/`). **דף הסוכן נשאר על המודאל הקיים** — שם המודאל משרת גם הצעות מחיר, PDF והיסטוריה, וזה המשטח המסוכן ביותר בפרויקט.

## אילוצים ארכיטקטוניים

`js/app.js` ו-`css/style.css` משותפים לשלושת הקטלוגים. לכן:

- מצב חדש `CONFIG.cartView` שברירת המחדל שלו `false` — דף הסוכן לא מקבל אותו ומתנהג בדיוק כמו היום.
- **כל ה-CSS החדש מגודר תחת `.cart-page`.** מודאל בלי המחלקה הזו נשאר בדיוק כפי שהוא.
- 10 דפי הקטגוריה מקבלים את המודאל מ-`js/catalog-shell.js` (שורות 45-120) במבנה זהה ל-`catalog/index.html`, ולכן שינוי ה-CSS חל עליהם בלי לגעת ב-HTML שלהם.

**מלכודת:** `orderModal` נסגר היום בלחיצה על הרקע (`e.target === orderModal`). בתצוגת מסך מלא הרקע הוא כל המסך — כלומר כל לחיצה תסגור את הסל. יש לנטרל את ההתנהגות הזו כש-`cart-page` פעיל.

## המבנה

### פריסה (`css/style.css`)

מבנה ה-DOM הקיים נשאר כמות שהוא; הפריסה נעשית ב-CSS בלבד:

```
.modal-overlay.cart-page
  .modal-content     → מסך מלא, בלי רקע כהה, בלי פינות מעוגלות
    .modal-header    → כותרת + "המשך בקנייה"
    .modal-body      → גריד: טבלת המוצרים מימין, טופס/אספקה/תאריך משמאל (≥1024px)
    .modal-footer    → בר פעולה דביק ברוחב מלא: סה"כ + כפתורי שליחה
```

במובייל (<1024px) הגריד קורס לעמודה אחת, והבר התחתון נשאר דביק.

### התנהגות (`js/app.js`)

**הפרמטר הוא `view=cart` ולא `cart=1`:** הפרמטר `cart` כבר תפוס לשיתוף עגלה בפורמט `cart=id:qty,id:qty` (כפתור "שתף קישור"), ושימוש חוזר בו היה מתנגש בפיצ'ר קיים.

- `openOrderModal()` — כש-`CONFIG.cartView`: מוסיף `.cart-page`, מבצע `history.pushState` ל-`?view=cart`, ומדווח `view_cart` ל-GA4 יחד עם `page_view` וירטואלי.
- `closeOrderView()` — פונקציה אחת שכל נתיבי הסגירה עוברים דרכה; מבצעת `history.back()` כשהמצב נדחף על ידינו, אחרת `replaceState`.
- מאזין `popstate` — סוגר את התצוגה בלחיצה על "אחורה".
- באתחול: `?view=cart` בכתובת + עגלה לא ריקה → התצוגה נפתחת. עגלה ריקה → הפרמטר מוסר, כדי שקישור ישן לא יפתח סל ריק.

### מדידה

`view_cart` ל-GA4 (`trackEvent`, קיים מסבב 29) + `page_view` וירטואלי עם `page_path` כולל `?view=cart`. יחד עם `begin_checkout` ו-`order_sent` הקיימים, המשפך נהיה: צפייה במוצר → הוספה לסל → **פתיחת סל** → שליחה.

## סבב עיצוב שני — כרטיס סיכום ושורות מוצר

אחרי הביצוע הראשון רועי העיר שהעמוד "נראה ריק ולא מקצועי". אבחון:

1. **המספר החשוב ביותר קבור** — "סה״כ לתשלום" ישב בפינת הפוטר באותו משקל ויזואלי כמו "סה״כ פריטים".
2. **אין היררכיה** — הכל שטוח על `--bg-body`, שום דבר לא מוגבה.
3. **חלל מת** — `grid-row: 1/span 99` עם `align-items:start` השאיר ~60% מהמסך לבן בסל קצר.
4. **זו טבלת נתונים, לא סל** — עמודות מק״ט/קטגוריה/יחידה עם תמונות 40px.
5. **הפרות טוקנים שהוכנסו בסבב הראשון** — `#fff`, `0 -2px 12px rgba(...)` קשיחים במקום `--bg-surface`/`--shadow-md`.
6. **אין מצב סל ריק.**

**החלטה: טיפול שונה לכל קטלוג, כי הקהל שונה.**

| | קהל | פתרון |
|---|---|---|
| `/catalog/` | מנהל רכש, עשרות מק״טים | טבלה קומפקטית נשמרת + כרטיס סיכום |
| `/care/` | לקוחה פרטית, 4 מוצרים | שורות מוצר עשירות (`.cart-rich`) + כרטיס סיכום |

**`#cart-summary-card`** — נבנה ב-`renderCartSummaryCard()`, מתעדכן מ-`updateSummary`. כש-`showPrices` הוא מציג סכום ביניים / הנחה / דמי משלוח / סה״כ; אחרת ספירת פריטים בלבד — **בקטלוג העסקי אין מחירים, וכרטיס עם סכומים היה חסר משמעות שם.** בדסקטופ הכרטיס `sticky` ו-`order:-1` בטור הצדדי.

**מניעת כפילות:** הכרטיס נושא את ה-CTA בדסקטופ ו**הבר התחתון מוסתר** (`min-width:1024px`); במובייל להפך — ה-CTA שבכרטיס מוסתר והבר נשאר צמוד ונגיש. כפתורי הכרטיס מפעילים את הכפתורים הקיימים (`send-whatsapp`, `send-email`, `clear-cart-btn`) כדי שלוגיקת השליחה תישאר במקום אחד.

**`.cart-rich`** — שימוש חוזר במבנה הכרטיסים שנבנה למובייל בסבב 23, בכל רוחב מסך: גריד `"img name name" / "img price price" / "img qty total"`, תמונה 72px. **אפס שינוי ב-`fillOrderTable`** — רק CSS על ה-classes `oc-*` הקיימים.

**`#cart-empty`** — מצב סל ריק עם חזרה לקטלוג; ה-CTA בכרטיס מקבל `disabled`.

גרסאות הסבב הזה: `app.js?v=34`, `style.css?v=23`, `sw` → `cache-v22`.

## גרסאות

`app.js?v=33`, `style.css?v=22`, `sw` → `cache-v21` (הסבב הראשון).

## אימות

1. פתיחת הסל משנה את הכתובת ל-`?view=cart`; "אחורה" סוגר את הסל ולא יוצא מהעמוד.
2. רענון בכתובת עם `?view=cart` פותח את הסל עם התוכן; עם עגלה ריקה הפרמטר מוסר.
3. לחיצה על אזור ריק בתצוגה **לא** סוגרת את הסל.
4. דסקטופ ≥1024px — שני טורים; מובייל 375px — עמודה אחת, בלי גלישה אופקית, הבר התחתון דביק.
5. `view_cart` נורה פעם אחת לפתיחה.
6. **רגרסיה:** `/agent/` — המודאל הישן בדיוק כפי שהיה, בלי `.cart-page`, בלי שינוי בכתובת. אפס שגיאות קונסול בשלושת הקטלוגים.
7. שליחת הזמנה מהתצוגה החדשה עובדת בשני הקטלוגים, והסכומים זהים לאלה שבהודעה.

# תעודת הזמנה PDF + הפיכתה להצעת מחיר

**תאריך:** 19.08.2026
**סטטוס:** בוצע (20.08.2026) — ממתין לפריסה ידנית של רועי

## הבעיה

היום, כשלקוח שולח הזמנה, רועי מקבל מייל טקסט ושורה בגיליון. שתי בקשות:

1. **PDF מעוצב עם תמונות המוצרים** לצד הגיליון — כדי שיהיה מסמך אחד קריא
   לליקוט ולתיוק, ולא רשימת טקסט.
2. **להפוך את ההזמנה להצעת מחיר** — הקטלוג העסקי מסתיר מחירים, ולכן ההזמנה
   מגיעה בלי מחירים; רועי רוצה להוסיף מחירים ולשלוח את המסמך חזרה ללקוח.

## תוצאות שלב 0 — הספייק (בוצע 19.08.2026)

הספייק רץ בפועל בענן, בשלוש גרסאות, והוא ששינה את שיטת המימוש.

### מה נבדק ומה נמצא

| נבדק | תוצאה |
|---|---|
| תמונות מרוחקות מ-aroam.co.il | ✅ מרונדרות |
| **WebP** ב-HTML→PDF | ✅ מרונדר (155 מ-176 התמונות הן webp) |
| עברית, RTL, ״ ו-׳, ₪ | ✅ תקינים |
| כתובת תמונה שבורה | ✅ אינה מפילה את המסמך |
| **`background-color` ב-HTML→PDF** | ❌ **נמחק לחלוטין** |

### הכישלון שקבע את השיטה

צבעי רקע נבדקו בחמישה אופנים — `background-color` על `div`, על `td`, על `th`,
תכונת `bgcolor` על `table` ועל `td` — **כולם נמחקו בהמרה**. המשמעות: הרצועה
הירוקה הכהה שבעיצוב המאושר לא הייתה מופיעה, והטקסט הלבן שעליה היה הופך
לבלתי קריא על רקע לבן. גבולות, פינות מעוגלות, פסי צד, צבעי טקסט ו-flexbox
דווקא שרדו — כלומר ההפסד היה ממוקד בדיוק במה שנושא את זהות המסמך.

### הפתרון: לבנות מסמך Docs במקום HTML

ב-HTML צבע רקע הוא הצעה שהממיר רשאי להתעלם ממנה; ב-Google Docs צבע רקע של
תא הוא **תכונה של הפורמט**, ולכן הוא שורד את הייצוא. הספייק אישר בפועל:
רצועת כותרת ירוקה כהה, שורת כותרות ירוקה עם טקסט לבן, פסים לסירוגין, פס
פסטל ליד ההערות, ורצועת סה״כ — כולם רונדרו.

**מגבלה אחת שהתקבלה במודע: אין פינות מעוגלות ב-Docs.** זה ההבדל היחיד שנותר
מול הדוגמה המאושרת.

**מגבלה שנייה, והיא הופכת את משימת התמונות הממוזערות לחובה:**
`appendInlineImage` של Docs **אינו מקבל WebP** — בספייק רק המוצר עם תמונת PNG
קיבל תמונה, ושתי שורות עם webp נותרו ריקות. 155 מתוך 176 תמונות המוצר הן
webp, ולכן בלי `images/thumbs/*.jpg` רוב התעודה תגיע בלי תמונות.

## למה לא לערוך את ה-PDF עצמו

PDF אינו פורמט עריכה: אין בו נוסחאות, ושינוי מחיר יחידה לא יעדכן סכום שורה,
סה״כ, הנחת סל או מע״מ. כל פתרון של "טופס PDF" היה מייצר מסמך שהמספרים בו
סותרים זה את זה — בדיוק התקלה שתוקנה בסבב 33 (`editablePrices`).

במקום זה מנצלים מה שכבר קיים בדף הסוכן:

| יכולת | איפה היא היום |
|---|---|
| עריכת מחיר יחידה בטבלה | `editablePrices: true` — `agent/index.html:46` |
| הדפסת הצעת מחיר ל-PDF | `printQuote()` — `js/app.js:2615` |
| שחזור עגלה מכתובת | פרמטר `?cart=id:qty,...` — `js/app.js:197` |
| מחירים טעונים מראש | 118 מתוך 176 המוצרים ב-`products.csv` |

הזרימה: קישור במייל ← דף הסוכן נפתח עם ההזמנה ← השלמת מחירים ← הדפסה ← שליחה.
כלומר הפיצ׳ר החדש הוא **קישור**, לא מנוע עריכה.

## ארכיטקטורה

```
לקוח שולח הזמנה
      │
      ├─ app.js: sendOrderBackupToGoogleScript()   ← נוסף image לכל פריט
      │
      ▼
Apps Script doPost()
      ├─ שורה בגיליון                              (קיים)
      ├─ buildOrderPdf_(data) → HTML → Blob PDF     (חדש)
      ├─ שמירה ל-Drive + קישור בעמודת "קובץ PDF"    (חדש)
      └─ MailApp.sendEmail(..., {attachments: [pdf]})
             └─ בגוף המייל: "פתח כהצעת מחיר" → /agent/?cart=...&customer=...
```

## רכיבים

### 1. `js/app.js` — שדה התמונה

`getCartItemsData()` (שורה 1992) מחזיר `id, name, category, qty, unit, price,
total, bundle, free` — **בלי `image`**. מתווסף `image: product.image || ''`.
תוספת בלבד; הסקריפט הישן מתעלם משדות שאינו מכיר.

### 2. `tools/make_pdf_thumbs.py` — תמונות ממוזערות

**זה הרכיב שמסיר את שני הסיכונים הטכניים העיקריים.** 155 מתוך 176 תמונות
המוצר הן `.webp` — פורמט שהממיר HTML→PDF של גוגל אינו מבטיח לרנדר; ובנוסף
הנתיבים מכילים עברית ורווחים, שדורשים קידוד נכון בכל שרשור כתובת.

הסקריפט (Pillow, כמו `tools/process_images.py` הקיים) יוצר לכל מוצר קובץ
`images/thumbs/<id>.jpg` — 120×120, רקע לבן, איכות 80. כך:

* הפורמט הוא JPEG — נתמך בכל ממיר.
* שם הקובץ הוא המזהה (`ניק001`), ללא רווחים.
* המשקל יורד מ-17KB ממוצע ל-~4KB, כלומר PDF קליל גם בהזמנה של 40 שורות.

הסקריפט קורא את **שלושת** קובצי המוצרים — `data/products.csv`,
`data/pricelist.csv` ו-`data/committee.csv` — כדי שגם הזמנות טיפוח וועד יקבלו
תמונות. אידמפוטנטי: מייצר רק תמונות חסרות או כאלה שהמקור שלהן חדש יותר.

**תלות סדר קריטית:** התמונות חייבות להיות חיות על `aroam.co.il` לפני שהסקריפט
בענן מנסה למשוך אותן. לכן `git push` של תיקיית `images/thumbs/` קודם לפריסת
גרסת ה-Apps Script — אחרת ה-PDF הראשון יֵצא בלי תמונות.

### 3. `tools/google-apps-script-orders.gs` — מחולל ה-PDF

פונקציה `buildOrderDoc_(data)` בונה מסמך Docs ומחזירה Blob של PDF:

1. `DocumentApp.create(...)` ← בניית הפריסה מטבלאות (ראה מפרט העיצוב למטה).
2. תמונות: `UrlFetchApp.fetch('https://aroam.co.il/images/thumbs/<id>.jpg').getBlob()`
   ואז `appendInlineImage(...).setWidth(44).setHeight(44)`.
3. `doc.saveAndClose()` ואז `DriveApp.getFileById(doc.getId()).getAs('application/pdf')`.
4. **`setTrashed(true)` על מסמך הביניים** — בלי זה כל הזמנה משאירה Doc זבל ב-Drive.
3. שומרת עותק לתיקיית Drive `הזמנות אהרוני — PDF`; הקישור נכתב לעמודה
   **"קובץ PDF"** שתתווסף **בסוף** `SHEET_HEADERS` — כמו שנעשה בסבב 30, כדי
   שהגיליון הקיים של רועי לא יזוז.
4. מצורפת ל-`MailApp.sendEmail` כ-`attachments`.

**עמידות בשגיאות:** כל הבלוק עטוף ב-`try/catch` נפרד. אם יצירת ה-PDF נכשלת,
המייל והשורה בגיליון נשלחים כרגיל בלי הקובץ, והשגיאה נרשמת. **הזמנה לעולם לא
תאבד בגלל תקלה ב-PDF.**

### 4. `agent/` — פרמטר לקוח + עיצוב אחיד

* **`?customer=`** — `printQuote()` פותח היום `prompt()`. הפרמטר, כשהוא קיים,
  משמש כערך ברירת המחדל ב-prompt (ולא מדלג עליו — רועי עדיין רשאי לתקן שם).
* **עיצוב** — ה-`headerDiv`/`footerDiv` ב-`printQuote()` מוחלפים בעיצוב
  המאושר, וטבלת ההזמנה מקבלת עמודת תמונה בהדפסה בלבד (`@media print`).
  נשמרים כלשונם: שורות החתימה, "ט.ל.ח", "המחירים אינם כוללים מע״מ",
  "תוקף ההצעה: 14 יום".

### 5. הקישור "פתח כהצעת מחיר"

נבנה בסקריפט: `https://aroam.co.il/agent/?cart=<id:qty,...>&customer=<שם>`,
עם `encodeURIComponent` על כל רכיב.

**מופיע רק כשלהזמנה אין מחירים** (`totalPrice` ריק) — כלומר רק הזמנות מהקטלוג
העסקי. בהזמנות טיפוח/ועד המחירים כבר סופיים, ודף הסוכן טוען `products.csv`
שאינו מכיל את מוצריהן.

## מפרט העיצוב (מאושר)

מסמך A4, RTL, שוליים 12/10 מ״מ. פלטת המותג בלבד: `#1A4231`, `#639C7D`,
`#8FD6A3`, `#F7FBF8`.

| אזור | תוכן |
|---|---|
| כותרת | רצועה ירוקה כהה: לוגו, שם העסק, "תעודת הזמנה", מספר ההזמנה, מועד קבלה |
| שני כרטיסים | פרטי הלקוח · פרטי ההזמנה (אספקה, מקור, סה״כ פריטים, סטטוס) |
| טבלה | **מימין לשמאל:** תמונה 44px · שם + קטגוריה · מק״ט · יחידה · כמות · [מחיר ליח׳ · סה״כ] |
| תג מבצע | "מבצע 2+1 — 1 חינם" מתחת לשם, כשיש `free>0` |
| סיכום | סכום ביניים · הנחה · דמי משלוח · סה״כ לתשלום — **רק כשיש מחירים** |
| הערות | הערות הלקוח, בבלוק עם פס ירוק |
| פוטר | מקור המסמך + טלפונים ומייל |

עמודות המחיר ובלוק הסיכום נשמטים לגמרי כשההזמנה בלי מחירים — אותה תבנית
משרתת את שני המקרים. `thead` מוגדר `table-header-group` ולכן שורת הכותרות
חוזרת בכל עמוד; `tr` מוגדר `page-break-inside: avoid`.

## הערה על סדר העמודות

ב-Docs עמודה 0 מרונדרת **בצד שמאל**. כדי לקבל תמונה מימין וכמות משמאל,
מערך העמודות נבנה בסדר הפוך: `[כמות, יחידה, מק״ט, מוצר, תמונה]`.

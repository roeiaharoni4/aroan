# תאריכי תוקף לכל סוג מבצע + הצגת התאריך ליד המבצע

**תאריך:** 31.7.2026 · **אושר ע"י רועי**

## הצורך
שני פערים שהתגלו בקוד הקיים:

1. **התאריך מוצג רק למבצעי חבילה.** `appendBundleInfo` ב-app.js יוצא מוקדם כשאין `bundle`,
   ולכן מוצר עם **מחיר מבצע רגיל** (או הנחת קטגוריה) + תאריך תוקף — לא מציג תאריך כלל.
2. **כל המבצעים הכלליים חולקים חלון תאריכים אחד** (`window`). אי אפשר להגדיר
   "הנחת שיער עד 1.9" ובמקביל "הנחת סל עד 15.8".

## החלטות שרועי אישר
- תאריכים נפרדים ל**כל** סוגי המבצעים (הנחות קטגוריה, הנחת סל, באנר) — לא רק לקטגוריות.
- התאריך מוצג **צמוד לתג המבצע** באותה שורה, בטקסט קטן (`עד 10.08`).

## מודל נתונים

`data/pricelist-promo.json` — כל מבצע מקבל `starts`/`ends` **אופציונליים**:
```json
{
  "banner":        { "enabled": true, "text": "...", "starts": "", "ends": "" },
  "cart_discount": { "enabled": true, "min_total": 350, "percent": 10, "starts": "", "ends": "2026-08-15" },
  "category_discounts": [
    { "category": "שיער",  "percent": 8,  "starts": "", "ends": "2026-09-01" },
    { "category": "כביסה", "percent": 12, "starts": "", "ends": "2026-08-20" }
  ],
  "window": { "starts": "", "ends": "" }
}
```

### כלל הכרעה אחיד (זהה לזה שכבר קיים למוצרים)
אם למבצע יש תאריך משלו (`starts` או `ends`) — **הוא קובע**, וצד חסר = בלי הגבלה.
אחרת חל ה-`window` הגלובלי. מבצע בלי תאריכים בכלל וללא חלון = תמיד פעיל.

זהו בדיוק אותו כלל שכבר פועל על `promo_start`/`promo_end` ברמת המוצר, כך שאין מודל
מנטלי חדש ללמוד, וקבצים קיימים בלי השדות ממשיכים לעבוד ללא שינוי.

## לוגיקה

### app.js
- `scopedActive(obj)` — עוטף את `promoActive` הקיים: תאריכי המבצע גוברים, אחרת החלון הגלובלי.
  מוחל על הבאנר, הנחת הסל וכל כלל הנחת קטגוריה בנפרד.
- `CATEGORY_RULES` — נשמר הכלל שהוחל על כל מוצר (`p._catRule`), כדי לדעת את תאריך הסיום
  הרלוונטי לאותו מוצר.
- `promoEndFor(p)` מורחב לסדר עדיפויות: תאריכי המוצר → תאריך כלל הקטגוריה שהוחל → החלון הגלובלי.
- **`appendPromoValidity(priceEl, product)`** (חדש) — מוסיף `<span class="promo-validity">עד DD.MM</span>`
  **inline** אחרי התג, לכל מוצר עם מבצע פעיל כלשהו (מחיר מבצע / הנחת קטגוריה / חבילה) **ותאריך סיום**.
  `appendBundleInfo` מצטמצם לתג החבילה בלבד — הפרדת אחריות.

### server.py
- `_load_category_discounts()` מחזיר `{קטגוריה: {'percent', 'ends'}}` ומסנן כללים שאינם בתוקף
  (לפי תאריכי הכלל, אחרת החלון). קוראיו מתעדכנים ל-`['percent']`.
- `_promo_dates_for(row, window)` מחזיר גם את תאריך כלל הקטגוריה כשהוא זה שחל.
- הגנרטורים (דפי קטגוריה/מוצר, סכמה, פיד) מציגים `עד DD.MM` ליד המחיר באותה לוגיקה.

### חשיפה לגוגל
`priceValidUntil` ו-`g:sale_price_effective_date` נגזרים מהתאריך **האפקטיבי** של המוצר —
כולל תאריך הנחת הקטגוריה. כך הפיד תמיד תואם למחיר המוצג ואין אי-התאמה ב-Merchant.

## עורך (`/admin/pricelist.html`)
- שדה "עד תאריך" לכל הנחת קטגוריה (הצ'יפ יציג `שיער 8% · עד 01.09`).
- שדה "עד תאריך" להנחת הסל ולבאנר.
- החלון הגלובלי נשאר, עם הבהרה שהוא ברירת המחדל.

## מחוץ לתחום
`data/products.csv` (B2B) ודף הסוכן — אין להם מבצעים כאלה, אפס השפעה. כל השינויים additive.

## אימות
1. מוצר עם מחיר מבצע בלבד + תאריך → מוצג `עד DD.MM` ליד תג "מבצע" (הפער העיקרי).
2. שתי הנחות קטגוריה עם תאריכי סיום שונים → כל אחת פגה בנפרד.
3. הנחת סל עם תאריך משלה → פגה בלי להשפיע על הנחות הקטגוריה.
4. מבצע בלי תאריכים → נופל לחלון הגלובלי (התנהגות קיימת נשמרת).
5. עורך: round-trip של כל שדות התאריך + שמירה לקובץ.
6. פיד וסכמה: `priceValidUntil` תואם לתאריך שמוצג.
7. קטלוג B2B ודף הסוכן ללא שינוי; מובייל 375px; אפס שגיאות קונסול.
